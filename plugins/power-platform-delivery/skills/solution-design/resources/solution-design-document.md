# Solution design document

Structure (Markdown, one file under `docs/design/`):
1. Context, scope, out of scope, assumptions
2. Requirements and fit-gap summary
3. Architecture overview (components, environments, integrations) with a diagram
4. Data model (Mermaid ER + table specs)
5. Security model (roles matrix, BUs, teams)
6. Apps (screens/forms/views), flows, agents, code components
7. Integration specs (system, direction, auth, volume, error handling)
8. ALM approach (solutions, environments, pipeline)
9. Non-functional: performance, limits, licensing, accessibility, data retention
10. Risks, decisions log, open questions

Keep decisions in a table: Decision | Options | Chosen | Reason.
